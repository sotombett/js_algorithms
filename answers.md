**1. В чем разница между временной сложностью O(n) и O(n²)? Приведите примеры алгоритмов с каждой сложностью.**

O(n) — линейная (один цикл, пример: findMax). 
O(n²) — квадратичная (вложенные циклы, пример: bubbleSort).


**2. Как работает алгоритм бинарного поиска и почему его сложность O(log n)?**

Делит отсортированный массив пополам на каждом шаге. Отбрасывает половину элементов, поэтому кол-во шагов равно log₂n.


**3. Какие преимущества и недостатки у пузырьковой сортировки по сравнению с другими алгоритмами сортировки?**

Плюсы: простой код, O(1) памяти. Минусы: O(n²) времени, медленная на больших массивах.


**4. Как можно оптимизировать функцию проверки на простое число для больших чисел?**

Проверять делители до Math.sqrt(n), идти с шагом 2 (пропускать четные), использовать вероятностные тесты.


**5. В чем разница между рекурсивной и итеративной реализацией алгоритма Фибоначчи?**

Рекурсивная: O(2^n), медленная, риск Stack Overflow. 
Итеративная: O(n), быстрая, O(1) памяти (цикл).


**6. Какие методы отладки вы использовали при реализации алгоритмов?**

console.log(), точки останова (Breakpoints) в браузере, написание юнит-тестов (runTest).


**7. Как работает алгоритм Евклида для нахождения НОД и почему он эффективен?**

Формула: gcd(a, b) = gcd(b, a % b). Эффективен из-за O(log(min(a,b))) — числа быстро уменьшаются.


**8. Какие edge cases (крайние случаи) нужно учитывать при реализации алгоритмов работы с массивами?**

Пустой массив, 1 элемент, дубликаты, отрицательные числа, null/undefined, неотсортированный массив (для бинарного поиска).


**9. Как можно улучшить функцию удаления дубликатов для работы с большими массивами?**

Использовать Set: [...new Set(arr)]. Дает O(n) времени вместо O(n²) у вложенных циклов.


**10. Какие принципы написания чистого кода вы применили при реализации алгоритмов?**

Понятные имена, одна функция = одна задача, обработка пустых массивов (early return), комментарии Big O, иммутабельность (копирование через [...arr]).
